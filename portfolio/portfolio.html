A music player with native apps for macOS, Android and Windows and a server that a group of friends can share. Open source, released (v0.3.1), and in daily use by its author.

What it does

  • One search across JioSaavn, YouTube Music and YouTube; the same recording from several sources is shown once and the best copy plays.
  • Shared and public playlists, friends, and notifications.
  • Jams: friends listen together on their own devices, in step, from one shared queue.
  • Timed lyrics with line-by-line translation, on-device on the Mac.
  • Offline downloads, prefetching of the next song, autoplay.

Engineering

  • Jam rules are written once (docs/jam.md) and implemented in all three codebases, with the server as the only source of truth and a shared playhead model.
  • Rooms survive server restarts: written on shutdown, resumed if back within 60 s.
  • Numbered SQL migrations; argon2 passwords; per-user rate limits behind a trusted proxy.
  • Privacy by design: no telemetry, no IP or search logs; YouTube lookups run on the user's device.

02 · Computer vision

Arya: unique-visitor counting

Counts how many different people passed through an event from the footage of several cameras over several days. Built for a three-day event with more than 300,000 expected attendees.

PyTorchMTCNNFaceNet (InceptionResnetV1, VGGFace2)ChromaDB · HNSW · cosineOpenCV

0
people counted twice or merged with someone else
57%

Pipeline

  • MTCNN finds faces; small or low-confidence detections are dropped.
  • A light IOU tracker follows each face within a clip, so a person walking past is embedded once, or again only when a sharper view appears.
  • FaceNet turns each face into a 512-d embedding; ChromaDB (HNSW, cosine) finds the nearest known visitor across all cameras and days.
  • Known visitors keep a quality-weighted running average of their embeddings, which gets more robust with each sighting.

Built for a long, large run

  • Checkpoints every 100 processed frames; a stopped run resumes where it left off.
  • Persistent vector store, so later days match against earlier ones.
  • Exports per-visitor records (first seen, cameras) to CSV and JSON.
  • Batch embedding on GPU; frame sampling configurable per deployment.
Demo path

demo/run_demo.sh renders three camera clips of synthetic people walking past (with overlap between gates and returning visitors), runs the pipeline and checks the count against the known answer. Drop real footage in videos/ and run python main.py for the real thing.

03 · Citizen-facing platform

Citizen complaints platform

The backend for a police complaints app: citizens verify their phone, file complaints with location and evidence, and track them; officers triage them from an admin side. The same shape as a patient app with a clinic back office.

FastAPIAsync SQLAlchemyMySQLJWTPillowOpenAPI

Citizen side

  • Phone OTP: 5-minute codes, 3 attempts, then a single-use action token to register or reset a password.
  • Login records GPS position, IP and device in a login log.
  • Complaints by type and category (validated pairs), free text, GPS, photos and video.
  • Evidence pipeline: type and size checks, EXIF orientation, resize and recompression, dated per-complaint storage.

Officer side

  • Dashboard by status and category with resolution rate; pending queue; user blocking; MIS report.
  • Every status change and note goes to an audit log.

Hardening

  • Rate limits on OTP, login and complaints; XSS, SQL and path-traversal checks; security headers; request audit logging.
  • Access tokens last 15 minutes; refresh tokens are hashed at rest and rotated on use.

04 · Real-time, location, offline

SonicNet: SOS without a network

Gets an emergency call (type, message, GPS fix, place) from a phone with no signal to a rescue command centre, by relaying it across nearby devices over Bluetooth LE discovery, Wi-Fi multicast or sound (data-over-audio), until one has an uplink.

PythonUDP multicastGGWave audio modemBLE (bleak)Flask-SocketIOSQLiteHMAC

Relay protocol

  • Every packet has a SHA-256 identity hash. A device forwards an SOS at most once: in the run above each call was heard about 60 times but repeats were dropped (149 of 243).
  • Hop count with a cap, so packets cannot circulate.
  • Server first, relay second: a device with an uplink delivers and stops the flood.
  • The server stores a call once even when it arrives through several gateways.

Command centre

  • Calls arrive live over WebSocket, triaged by type and message keywords (medical, fire, disaster → critical).
  • Each call shows its location, relay count and route, and can be acknowledged.
  • Audio path: an HMAC-signed, chunked rescuer ↔ survivor status exchange over speaker and microphone, for devices with no radio at all.

06 · Shipped product · unvelit.in (now sunset)

Unvelit: an anonymous college forum

Unvelit (unvelit.in) was an anonymous forum for college students that our team built, launched and ran until it was sunset. Anonymous posting with image and video uploads is a risky combination, so every post passed through our own moderation service before anyone saw it. Paid moderation costs money per call, so a repost of something already moderated is recognised and its verdict reused.

FastAPIMySQLperceptual hashingSightEngineGeminiOpenCV

How it works

  • Images: a 64-bit perceptual hash per upload. Near-duplicate lookup is a single MySQL query, BIT_COUNT(hash ^ ?) ≤ 8: Hamming distance as a popcount, with no vector database.
  • Video: five sampled frames hashed and screened one by one; screening stops at the first frame that fails.
  • Text: Gemini moderation with conversation context.
  • Batch endpoints run concurrently; every decision and its reason go to an audit table.

Found and fixed while building the demo

The first version used 16-bit hashes, where about 60% of unrelated images look alike, so a new upload could inherit some other image's "pass". Moving to 64-bit hashes took wrong matches from 4 in 9 to 0 in 9 with the same repost detection, and old rows migrate automatically.

Lead capture over web, WhatsApp and voice

Three iterations of the same business problem, an assistant that answers from a company's own content and turns conversations into qualified leads, from a managed multi-client service to a single agent graph.

LeadGenius

A managed chatbot service for many client businesses. An admin onboards a client and crawls their site into a vector store; the widget answers with RAG and detects leads through LLM function calling.

Celery workers run email and WhatsApp follow-up sequences that pause when the lead replies; typing TALK hands the chat to a human. Client dashboards show leads and chat history.

One knowledge base behind a website chatbot, a WhatsApp Business bot (Twilio) and a browser voice agent built on CrewAI, with all leads and transcripts in one dashboard.

AutoStream agent

A LangGraph state machine for a SaaS sales funnel: inquiry, qualification, capture. RAG over pricing and features, slot filling into a typed state, structured output for the captured lead, and session memory through a checkpointer.

Chosen over a multi-agent framework because a sales funnel needs deterministic transitions. Ships with Docker.

Real-time voice bot pipeline

A WebRTC media server in Node.js with streaming voice-activity detection and barge-in: when the caller starts speaking, the bot's reply is cut off, with a 300 ms target. Raw 16-bit, 16 kHz PCM with a 10 ms heartbeat that keeps the RTP stream alive during silence. Speech recognition and synthesis are stubs, ready for any STT/TTS provider.
